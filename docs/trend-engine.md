# Core trend engine

All formulas below use completed, causally available regular-session bars, explicit `as_of_ns`, and Python finite floats. A missing required input gives `null`, never zero. `TrendFeatureEngine.compute(store, as_of_ns)` returns immutable `TrendFeatureSet` with per-symbol typed `SymbolTrendFeatures`, broad-market scores, counts, coverage, flags, and explainable contributors. No regime label is assigned.

## Per-symbol diagnostics

| Name | Definition and units | Minimum and missing behavior |
| --- | --- | --- |
| `trend.return.<symbol>.<horizon>` | Simple return `P_current / P_reference - 1`; unbounded dimensionless ratio. A separate `log_return(a,b)=ln(b/a)` utility is available for strictly positive prices. | Two causal reference/current prices; reference must be positive. Missing, nonpositive reference, and invalid log price produce `null`. Zero is a real flat return. |
| `trend.slope.short.<symbol>`, `trend.slope.long.<symbol>` | OLS of `y_i=ln(close_i)` on `x_i=(bar_end_i-first_bar_end)/3.6e12` hours. `slope = Σ(x_i-x̄)(y_i-ȳ)/Σ(x_i-x̄)²`; `intercept=ȳ-slope*x̄`; `R²=max(0,min(1,1-Σresidual²/Σ(y_i-ȳ)²))`. Slope units are log return/hour. Identical prices have slope 0 and R² 1. Default windows: 5m and 30m. | Configured minimum 3 distinct-time positive-price bars. Otherwise slope/intercept/R² are `null`. Actual irregular timestamps enter OLS. |
| `trend.persistence.<symbol>` | Among nonzero adjacent log returns in the long window, fraction whose sign matches the net log move. Range `[0,1]`; flat/net-zero is 0. | At least 3 positive-price bars; otherwise `null`. |
| `trend.path_efficiency.<symbol>` | `abs(ln(P_last/P_first)) / Σ abs(ln(P_i/P_(i-1)))`, capped at 1; range `[0,1]`, zero path gives 0. | At least 3 positive-price bars; otherwise `null`. Diagnostic, not independently weighted into the default score. |
| `trend.agreement.<symbol>` | `abs(sum(nonzero horizon signs))/number_of_nonzero_signs`, range `[0,1]`. Opposing signs set `HORIZON_DISAGREEMENT`; all zero gives 0. | At least one return; no returns gives `null`. Missing horizons are excluded and flagged as insufficient history. |
| `trend.acceleration.<symbol>` | `short_slope_per_hour - long_slope_per_hour`, log return/hour. Positive means the recent slope is more upward; negative means more downward. This is a slope differential, not a physical second derivative. | Both configured regressions must exist; otherwise `null`. |
| `trend.distance.<symbol>` | `(last_close / arithmetic_mean(long-window closes))-1`, dimensionless. The raw distance is preserved. | Positive mean and at least 3 bars in engine output; otherwise `null`. |

For each numeric diagnostic, the input bars' effective times must be no later than `as_of_ns`. Future samples cannot affect a past result. No full-history z-score or percentile is fitted. Fixed-scale normalization `N(x,s)=tanh(x/s)` maps finite values to `(-1,1)`; scales are positive configuration values, and raw values remain in typed results and contributors. No outlier is dropped or clipped by a future-fitted threshold.

## Scores and broad market

The per-symbol signed score uses these normalized components: mean available horizon return transformed by `N(., return_scale)`; long slope transformed by `N(., slope_scale_per_hour)*R²`; `sign(long_slope)*persistence`; slope differential transformed by `N(., acceleration_scale_per_hour)`; and distance transformed by `N(., return_scale)`. Default weights are respectively `0.40, 0.25, 0.15, 0.10, 0.10`. Weights are validated to sum to 1. If a component is mathematically unavailable, weights of available components are renormalized by their sum. A symbol score additionally requires at least `min_regression_samples` long-window bars. Every contributor records the raw value, normalized value, and exact weighted contribution; the score is their sum. The score range is `[-1,1]`.

`market_direction_score` is the weighted mean of available per-symbol signed scores. Default index weights are equal. Custom positive finite weights have canonicalized symbol keys and must cover every configured broad-market symbol; available weights are renormalized if a symbol is missing. `index_agreement = abs(Σ weight_i*sign(score_i))/Σ_nonzero weight_i`, with all-zero scores giving 0. Opposing index signs set `INDEX_DISAGREEMENT`. `trend_score = market_direction_score * index_agreement`: it retains direction while discounting conflicting indices. Both scores are `null` when available/expected broad-market symbol coverage is below `minimum_market_coverage` (default 0.67). Individual scores remain visible. These are transparent research scores, not PnL-fitted coefficients or trade signals.

## Quality and configuration

Per-horizon results expose sample count, expected count, and coverage. Missing reference or insufficient regression samples set `INSUFFICIENT_HISTORY`; coverage below `minimum_window_coverage` (default 0.8) sets `INSUFFICIENT_WINDOW_COVERAGE`. The engine preserves mathematically valid values under low coverage and flags the weakness. Bar freshness uses the MCE-2 explicit-as-of bar limit; `age > limit` sets `STALE_DATA` and `SOURCE_STALE` without automatically discarding a valid historical result. Missing symbols set `PARTIAL_UNIVERSE` and `LOW_COVERAGE`. No available score or a below-threshold market fraction is `UNUSABLE`; a score with any flags is `DEGRADED`; complete unflagged output is `GOOD`. Configurable horizons, cadence, slope lengths, sample/coverage thresholds, normalization scales, component weights, and index weights all enter the configuration fingerprint. Logging does not.

`apply_trend_to_snapshot(result, snapshot=None)` merges only the existing schema-1.0 trend/direction fields, index scores, finite scalar feature values, contributors, and quality. Other analytics and regimes stay uncomputed. It requires identical `as_of_ns`, preserves unrelated snapshot content, and stamps the current producer engine version. Engine version is 0.3.0; schema stays 1.0.
