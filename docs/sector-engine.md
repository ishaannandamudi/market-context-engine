# Sector and relative-strength engine (MCE-6)

SectorFeatureEngine(config, universe_provider=None, calendar=None).compute(store, as_of_ns) reads only the causal store, typed sector membership, configured XNYS calendar, and explicit time. It returns immutable SectorFeatureSet and SectorContext models. apply_sectors_to_snapshot projects continuous scores and evidence into schema 1.0; it assigns no regime or trading recommendation.

## Point-in-time sector universe

SectorMembership extends the MCE-5 membership contract with a canonical lower-case sector name. A record is active when effective_from_ns ≤ T < effective_to_ns (or no end) and available_at_ns ≤ T. Bounds are inclusive/exclusive respectively; adjacent records allow a weight update or a technology-to-energy reclassification at the exact transition time. SectorMembershipTimeline rejects overlapping intervals for an assignment and, by default, across sectors for one symbol. Nonexclusive membership may be configured, but a symbol then legitimately contributes to more than one sector. The engine rejects provider snapshots whose clock differs from the requested time.

The default provider is a deterministic timeline from features.sectors.groups. No sector list or historical constituents are hard-coded. Historical sector calculations query membership at each historical endpoint, so future additions, removals, reclassifications, delayed membership availability, and weight changes cannot rewrite earlier results. A current constituent list used for old dates would introduce survivorship bias; empirical research needs genuine point-in-time membership from a future provider. Preserve that provider dataset/version with the observation store and config fingerprint.

Optional features.sectors.proxy_mapping labels sector ETF/index instruments explicitly as proxies. The broad reference is features.sectors.reference_symbol, default SPY. Constituents, sector proxies, and the broad reference must use consistent price adjustment within the configured source. The declared adjusted/raw/unknown status affects evidence quality; MCE-6 does not ingest corporate actions or verify adjustment per bar.

## Price, return, breadth, and strength formulas

Only completed regular-session bars from the configured source, effectively available by T, are read. The latest same-day causal close is the current price. A member is stale if its bar end or effective time is older than freshness.bar_limit_ns; stale and missing members remain in the expected count but contribute no current return. Daily comparisons use the close ending exactly at the previous XNYS trading-session close. Premarket and after-hours bars, a future daily close, and implicit forward fills are excluded. The exchange calendar handles weekends, holidays, DST, and early closes.

For a horizon h, rᵢ,h = current close / causal horizon reference − 1. Defaults expose session, 1d, 5d, 5m, 30m, and 20d. The score's short/medium/long horizons default to session/1d/5d. Session uses the first available regular bar's open; trading-day horizons use the exact previous trading-session close N days back. Elapsed horizons use a completed boundary bar, with the regular open used when the requested elapsed boundary is exactly the session open and the first bar is present. A missing reference yields null. Return units are decimal, and horizons are separately named.

Absolute sector return is the mean of available constituent rᵢ,h only when valid-member coverage for that horizon meets the configured threshold. If every active member has a finite nonnegative point-in-time weight, the separate weighted return is Σvalid wᵢrᵢ,h / Σvalid wᵢ. Its original-universe weight coverage, Σvalid wᵢ / Σactive wᵢ, is reported for each horizon, and the weighted return is withheld below its own threshold. Missing weights never become inferred market-cap weights. Proxy return is a third, explicitly labeled series. Proxy divergence is equal-weight constituent return minus proxy return.

Relative return is equal-weight sector return minus the configured broad-reference return for the *same* horizon. Absolute and relative returns are independent fields; a sector can rise in absolute terms while lagging a faster-rising market. Cross-horizon agreement is positive only if all available score-horizon relative returns are positive, negative only if all are negative, mixed otherwise, and unavailable if none exist. Sector momentum is short relative return minus medium relative return. Sector acceleration is current momentum minus the previous completed trading session's momentum; both are decimal return differences and require their input horizons.

Sector breadth uses the MCE-5 direction primitive on each valid member's current price versus previous trading-session close. A/D/unchanged use the configured tiny breadth tolerance; net advance fraction is (A−D)/valid members in [−1,1]. Breadth score is this net fraction only when the sector meets minimum member count and member coverage. Reference participation at configured 5/20/60 previous-session SMA levels retains comparable counts and is null when no member has full history. Breadth/proxy divergence is net advance fraction minus the sign of proxy's previous-close return, in [−2,2]; it is unavailable without a proxy observation.

Normalize any relative return x with f(x)=x/(|x|+scale), default scale 0.01. The relative-strength score combines normalized short, medium, and long relative returns with default weights 0.35/0.30/0.25 and breadth confirmation with weight 0.10. The breadth term is net advance fraction multiplied by the weighted mean absolute magnitude of the *available normalized relative returns*. It is zero when the sector exactly matches the market across its available score horizons, so absolute breadth alone does not imply relative outperformance. Available weights are renormalized, but at least one relative return is required. The score is bounded in [−1,1] and suppressed below member-count/coverage thresholds or for unusable membership. Contributors store every effective weighted term and sum to the score. Absolute-strength score is f(medium absolute return), kept separate. Proxy and trend scores are not added as independent terms.

## Volatility, ranks, persistence, and rotation

For every completed historical trading day, the engine reconstructs each sector's equally weighted composite daily simple return from the members valid *and known at that day's close*. Missing members reduce coverage; a day below minimum count/coverage becomes a missing composite observation. On a contiguous window of N composite returns, realized volatility is sqrt(A × sample variance of log(1+r)), an annualized decimal using the MCE-4 sample-variance primitive; A is the configured trading sessions per year (default 252). Configurable short/medium/long defaults are 5/20/60 sessions. The headline realized_volatility is medium. A short-volatility percentile uses the MCE-4 prior-only midrank distribution over a configurable baseline; the current short volatility is excluded from that baseline. Market volatility uses the broad-reference daily returns over the medium window. Relative volatility is sector medium volatility / market medium volatility only when the denominator is positive. Zero or unavailable market volatility yields null. High relative volatility is context, not a negative score.

Only sectors with a valid relative-strength score enter ranking. Sort by descending score, then canonical sector name for a deterministic tie. Rank is one-based. Cross-sectional percentile is (N−rank)/(N−1), or 0.5 for the sole valid sector. Leader and laggard, top-minus-bottom score spread, and leader transition require at least minimum_valid_sectors (default two). Leadership concentration is HHI of *positive* sector scores normalized to unit positive-score mass; it is null when no score is positive. Sector score dispersion is the top-minus-bottom range, a narrow diagnostic rather than a full dispersion model.

Historical ranks are recomputed at previous completed trading-session endpoints with those endpoints' membership and available bars. Leadership persistence is the fraction of the current and previous four snapshots in the top ceil(N/4) ranks, requiring all five observations and at least two ranked sectors each time. Rank change is previous rank minus current rank (positive means improved rank). Relative-strength change is current minus previous score. Rotation velocity is the mean absolute rank move of common valid sectors across the current and previous three trading-session transitions, divided at each transition by max(sector counts)−1. It lies in [0,1], is measured per trading-session transition, and is null without complete comparable history. A future snapshot never enters a past rank or velocity.

## Quality, feature names, and snapshot

Every SectorContext exposes expected/valid/stale member counts, member coverage, per-horizon coverage, point-in-time weight coverage, per-member evidence, and quality flags. Low coverage retains raw breadth counts but withholds headline score and low-coverage horizon returns. Missing broad-reference data withholds relative returns and scores. Missing optional proxy data leaves proxy metrics null. Evidence quality is member coverage × available relative-horizon fraction × membership-source factor × adjustment factor × known medium-horizon weight coverage (or one if weights are absent); missing medium volatility halves it. It measures evidence completeness, not predictive confidence. Generic flags describe partial universe, stale data, insufficient history, missing sector/market data, and degraded source.

Stable snapshot names use sector.<canonical_name>.<metric>, for example sector.technology.return.5d, sector.technology.weighted_return.5d, sector.technology.relative_return.5d, sector.technology.relative_strength, sector.technology.breadth, sector.technology.realized_volatility, sector.technology.relative_volatility, sector.technology.rank, and sector.technology.persistence. Cross-sector names include sector.rotation.velocity and sector.leadership.spread. Null scalar values are omitted from feature_values. Snapshot sector_scores holds valid relative-strength scores; existing trend, volatility, and breadth evidence is preserved. Categorical market regimes remain UNKNOWN unless independently populated elsewhere.

All result-relevant features.sectors settings, including groups, exclusivity, proxies, reference, horizons, coverage, weights, volatility windows, and rotation windows, enter the config fingerprint. Synthetic fixtures and the manual benchmark use no network or credentials. A full correlation engine, correlation matrices, correlation regime context, basic systemic co-movement or clustering, and stress/liquidity context remain for MCE-7.
