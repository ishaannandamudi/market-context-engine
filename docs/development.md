# Development

Use Python 3.11 or newer. From the repository root:

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/pytest
.venv/bin/pytest --cov=mce --cov-report=term-missing
.venv/bin/ruff check .
.venv/bin/ruff format --check .
.venv/bin/mypy
git diff --check
```

`mce.models` defines domain contracts; `mce.providers` defines adapter protocols and the in-memory historical reference; `mce.calendar` wraps XNYS schedules; `mce.ingestion` validates and tags batches; `mce.replay` stores/activates causally available observations; `mce.features` computes trend, realized volatility, point-in-time market breadth, sector context, correlation, dynamic factors, market-network topology, intraday seasonality, dispersion, liquidity, stress, deterministic regimes, and descriptive regime-transition analytics; `mce.statistical` prepares causal research datasets, training-only transforms, session splits, descriptive latent-state evaluation, and statistical regime models; `mce.quality` handles freshness and coarse quality; `mce.config` loads typed settings; `mce.serialization` creates canonical JSON; `mce.reproducibility` hashes result-relevant configuration. Tests use fixed synthetic records in `tests/fixtures`.

Keep domain models independent of provider SDKs and network I/O. Use UTC integer nanoseconds, explicit availability times, typed enums, finite scores, and `None` for unavailable analytics. Add focused modules when a later phase needs them, not empty placeholders. Do not add global logging handlers in library code; applications may use `mce.logging.UTCFormatter` and `get_logger`.

Configuration is frozen and accepts `MCE_<SECTION>__<FIELD>` environment variables. The fingerprint uses an explicit allowlist: `market`, `provider`, `snapshot`, `ingestion`, `freshness`, `replay`, `features`, `statistical`, and `reproducibility` settings. Operational `engine.log_level` is excluded. There are no secrets or absolute paths in the current config. Future secrets must remain outside the fingerprint and repository; future result-relevant fields must be added to the allowlist deliberately. Universe symbol groups and sector mapping are configurable; the broad-market default is `SPY`, `QQQ`, `IWM`, while sector/volatility/breadth groups start empty.

MCE-2 added `exchange-calendars` for maintained holiday/early-close schedules. MCE-3 through MCE-6 added no direct runtime dependency. MCE-7 adds NumPy explicitly for covariance, rank/correlation matrices, and eigen diagnostics; MCE-8 through MCE-9 reuse it for cross-sectional moments. MCE-10 through MCE-16 add no runtime dependency; MCE-16 reuses NumPy for explicit linear quantiles and robust baselines. SciPy, scikit-learn, and networkx are not dependencies. Standard-library `zoneinfo` handles local interpretation once the exchange schedule is known. Pin dependency versions when replay output must be reproducible across machines and dates. Run `.venv/bin/python benchmarks/trend.py`, `benchmarks/volatility.py`, `benchmarks/breadth.py`, `benchmarks/sectors.py`, `benchmarks/correlation.py`, `benchmarks/dispersion.py`, `benchmarks/stress.py`, `benchmarks/regime.py`, `benchmarks/regime_transition.py`, `benchmarks/statistical.py`, `benchmarks/statistical_models.py`, `benchmarks/factors.py`, `benchmarks/network.py`, or `benchmarks/seasonality.py` for manual, non-CI measurements.

The engine version lives only in `mce/version.py`; the package reads it dynamically. The separate schema version is in the same file. Before changing the snapshot, review JSON compatibility, causal semantics, and AME deserialization. Additive optional fields can be a minor schema change; incompatible changes need a new major version and an explicit migration strategy.

MCE-20 promotes the engine to 1.0.0 while leaving snapshot, statistical, options, and macro schemas at 1.0. The final validation checklist is in [production readiness](production-readiness.md). The consolidated benchmark is `.venv/bin/python -m benchmarks.full_pipeline --symbols 500 --bars 30 --snapshots 2 --prior-sessions 22`; it measures replay ingest plus orchestrated snapshots and reports stage times separately. The local CLI and WSGI adapter add no runtime dependency.

Manual MCE-3 benchmark on Python 3.11.16, macOS 26.6.2, arm64: 1,170 one-minute bars (three symbols, one 390-minute session), 20 five-minute snapshot times, all default horizons: about 0.5 seconds total, about 25 ms per snapshot. This is a local observation, not a CI timing gate. Run `python benchmarks/trend.py` to measure your machine.

Manual MCE-4 benchmark on the same Python/macOS/arm64 environment: 70,200 one-minute bars across 60 regular sessions and three symbols, 20 snapshots, close-to-close, intraday RV/BV, Parkinson, Garman–Klass, Rogers–Satchell, and Yang–Zhang enabled: 0.925 seconds total, 46.2 ms per snapshot. Data construction is excluded from timing. This is a local observation, not a CI timing gate. Run `python benchmarks/volatility.py` to measure your machine.

Data construction is excluded from timing. This is a local observation, not a CI timing gate. Run `python benchmarks/breadth.py` to measure your machine.
