# Macro and scheduled-event context (MCE-18)

`MacroContextFeatureEngine` consumes provider-neutral `MacroContextInput` batches or an explicitly built `MacroHistoryIndex` at UTC nanosecond clock `T`. It does not scrape data, call providers, forecast economic releases or Fed decisions, infer why prices moved, or recommend trades. The typed result and optional schema-1.0 snapshot projection are **descriptive**. MCE-9 market stress, MCE-17 options stress, deterministic regimes, and the statistical feature schema are unchanged. Scheduled-event proximity measures nearby scheduled information; it is **not** expected return or volatility.

## Contract, availability, and revisions

The contract requires `macro_context_schema_version="1.0"`; incompatible versions fail explicitly. `MacroContextAdapter` parses JSON-compatible payloads and ignores unknown additive top-level fields. A source batch has source ID, semantic version, optional fingerprint, calculation `as_of_ns`, availability `available_at_ns`, quality, typed observations, releases, and schedule versions. No credentials or endpoint details enter quantitative configuration. Children identify their source and must be known by the batch calculation clock. A batch becomes visible only at its availability time; child release/availability, vintage, consensus, and calendar-announcement clocks remain preserved. If a source delivers a historical record late, the batch availability is its effective MCE availability. Observation period end is **not** the release time.

`MacroObservation` carries a typed category, series ID, cadence, value, explicit unit, period end, release time, availability, vintage time, preliminary/final/revised status, quality, and an explicit tenor in months for Treasury yields. Categories cover policy rates, Treasury yields, inflation, employment, unemployment, wages, growth, activity, consumer, housing, credit, liquidity, and other. Units include percent, decimal rate, basis points, percentage points, index level, annualized rate, millions, thousands, and ratio. Annualized rate values are used as supplied; the engine does not annualize them. Rate levels are converted to percent; rate differences and curve spreads are percentage points. A source series cannot silently change category, unit, cadence, or Treasury tenor. Negative rates are permitted. Nonfinite inputs and decimal rates that cannot be represented after percent conversion are rejected; raw values are never silently clipped. If valid extreme values overflow a derived difference, that derived value is missing while raw evidence remains available.

`MacroRelease` separately carries event ID, actual, optional **externally supplied** consensus, its pre-release availability time, optional prior and revised-prior values, unit, period, release/availability/vintage clocks, revision status, and quality. Consensus and its timestamp must be supplied together, and consensus must have been known no later than the release. No consensus is synthesized. Releases and observations can coexist without turning every snapshot into a new release.

`ScheduledMacroEvent` carries a stable source-scoped event ID, typed event type, scheduled time, calendar availability, supplied low/medium/high importance, affected series, optional release window, prior scheduled time for a revision, status, and quality. Event types include FOMC decision/minutes, CPI/core CPI, PCE/core PCE, payrolls, unemployment, claims, GDP, retail sales, ISM, sentiment, Treasury auction, and other. Keep the **same `(source,event_id)` across rescheduling**; use a new `calendar_available_at_ns` version. A cancellation has status `cancelled`. Duplicate exact versions are deduplicated; conflicting same-clock versions fail instead of double-counting.

`MacroHistoryIndex` sorts batches by effective availability, keeps immutable per-series vintage states, and builds point-in-time calendar states. At `T`, a series uses the newest available vintage of its latest observation period. For a previously released period revised at `T2`, replay between initial release `T1` and `T2` sees the original value; replay at or after `T2` can see the revision. History comparisons use distinct **prior periods** with their latest vintages known at `T`, never repeated snapshot minutes or multiple revisions of one period. Event lookup selects the latest schedule version known at `T`; an event announced or rescheduled after `T` cannot alter past proximity. Calendar lookup uses event-time binary search after the applicable schedule state is selected. Callers should build the index once and reuse it across many snapshots.

## Formula and missing-data reference

All time windows below are causal at `T`. A missing value is `None`; zero is a measured zero. Raw source evidence remains available when a derived headline is withheld.

| Feature | Formula and units | Required data, timing, and missing behavior |
| --- | --- | --- |
| `macro.event.next.hours`, `macro.event.next_high.hours` | `(scheduled_at−T)/3.6e12`, in hours | Earliest known upcoming event and earliest known upcoming **high-importance** event. Missing if none; event at exactly `T` is upcoming. |
| `macro.event.upcoming_count_24h`, `macro.event.high_importance.count.24h` | Counts in `[T,T+24h]`; nonnegative integers | Known, eligible scheduled events. A known empty calendar with an acceptable source yields zero; an unavailable calendar, unacceptable source, or ineligible event in the window yields missing. Separate configurable density-window count and weighted count follow the same quality rule. |
| `macro.event.proximity_score` | `1−Π(1−w_i·max(0,1−(scheduled_i−T)/H))`, clipped to `[0,1]`; `H` defaults to 24h; supplied importance maps to configurable low `.25`, medium `.50`, high `1.0` | Eligible upcoming events inside `H`. Multiple events increase score transparently. Known empty calendar with an acceptable source yields 0; unknown calendar, no acceptable source, or an ineligible event inside `H` yields missing. This is scheduled information proximity, not expected market impact. |
| `macro.event.recent.seconds_since_release` | `(T−release_at)/1e9`, seconds | Most recent available released event within configurable recent horizon (default 72h). A schedule by itself is not a released result; no market move is attributed to the event. |
| `macro.series.<source>.<id>.surprise` | `actual−consensus`, in the release's explicit unit | Both supplied and available, with consensus known by release. Missing without consensus. Preliminary/revised values retain their vintage and status. |
| `macro.series.<source>.<id>.surprise_z` | `raw_surprise/(1.4826·MAD(prior raw surprises))`, unitless | At least `minimum_history` (default five) distinct prior releases of the same series and unit, available at `T`. Zero scale gives 0 only for zero current surprise; otherwise missing. This is not a forecast-error probability. |
| `macro.series.<source>.<id>.percentile`, `.robust_z` | Prior-period midrank `(count(prior<current)+0.5 count(prior=current))/N` in `[0,1]`; `(current−median)/(1.4826·MAD)` unitless | At least `minimum_history` prior distinct observation periods. Zero MAD gives z=0 at the median, otherwise missing. The current release/revision never enters its own baseline. |
| `macro.series.<source>.<id>.change` | Current observation minus previous distinct-period observation, in the series unit | Missing without an earlier period; revisions of the same period do not inflate observation count. |
| `macro.policy.rate`, `.delta` | Selected supplied policy rate in **percent**; current minus prior period in **percentage points** | A cadence-valid typed policy-rate series, optionally selected by configured ID. Missing without appropriate observations. No nominal-rate-only restrictiveness judgment or next-decision prediction. |
| `macro.policy.trailing_change_count`, `.cumulative_change` | Count of changed rate levels within configured 365-day lookback; current minus first observed level in that window, in percentage points | Explicit prior policy history. Cumulative change needs at least two records. Time since last observed change is measured from its availability time. |
| `macro.curve.2s10s`, `.3m10y`, `.30y5y` | `y10−y2`, `y10−y3m`, `y30−y5`, in percentage points | Matching supplied tenors, converted to percent, with observation periods within configured two-day curve skew. Missing individually when either tenor is absent. |
| `macro.curve.level`, `.mean_level` | Supplied 10y yield; arithmetic mean of eligible available tenors, in percent | `level` missing without 10y; mean missing without yields. No PCA or inferred latent factor. |
| `macro.curve.curvature` | `y5−[y2+(y10−y2)·(60−24)/(120−24)]`, in percentage points | 2y, 5y, 10y. Positive means the 5y belly is above the endpoint line. |
| `macro.curve.inversion`, `.inversion_magnitude` | Inverted if either available 2s10s or 3m10y spread is negative; magnitude is the largest negative-spread absolute value, otherwise zero, in percentage points | At least one spread. A negative curve is context, **not** a guaranteed recession or trading signal. |
| `macro.curve.change_10y_1d`, `_5d`, `_20d` | Current 10y yield minus latest same-series prior value at or before `current period end−h` days, in percentage points | Explicit prior yield history within cadence-aware seven-day tolerance of each reference. Missing otherwise. Five-day parallel shift is the mean of available tenor changes when at least two exist; 2s10s steepening is `Δ10y−Δ2y` over five days. |
| `macro.<inflation/growth/labor>.value`, `.surprise`, `.surprise_z` | Latest typed member's raw value/unit and release surprise; no cross-unit average | Available observations/releases in that dimension. Full per-series evidence remains available for mixed payroll/unemployment releases. |
| `macro.<dimension>.normalized_signal` | Median of available category-oriented surprise z values, unitless | Inflation: higher means more inflation pressure; growth/activity: higher means stronger growth; payroll/wages: higher means labor strength; unemployment: **lower** means labor strength. Missing without comparable causal z values. These are separate axes, not one good/bad market score. |
| `macro.stress.rates`, `.curve`, `.surprise` | `min(1,abs(Δ10y_1d)/0.5pp)`, `min(1,inversion_magnitude/1pp)`, `min(1,max(abs(surprise_z))/3)` | Distinct **observed** rates, curve, and released-surprise evidence. Missing component stays missing. Scales are configurable; clipping applies only to normalized scores, not raw inputs. |
| `macro.stress.score` | Weighted mean of available components, default rates `.35`, curve `.25`, surprise `.40`, renormalized over active components; `[0,1]` | At least two components by default; otherwise missing. Scheduled-event proximity/density is deliberately **separate** and MCE-9 stress is not reused. This is descriptive macro dislocation, not a prediction. |

## Cadence, quality, and projection

Freshness is measured from each observation or release **period end**, not a generic intraday transport timestamp. Default cadence limits are daily 7 days, weekly 21 days, monthly 70 days, quarterly 180 days, and event-driven 365 days. Observation and release freshness are tracked separately when both exist. A several-week-old monthly CPI observation can be cadence-valid; a much older one is flagged stale. Replaying every minute does not create new macro observations. The source batch and each record retain their own quality. Low-quality or stale raw records remain inspectable, while curve, policy, normalized dimension, and stress headlines require eligible records. Insufficient history, unavailable calendar, degraded source, stale series, and missing curve tenors produce quality flags. Snapshot source freshness reports effective source-data times and series staleness separately from source calculation metadata.

`apply_macro_context_to_snapshot` replaces only the `macro.*` scalar namespace. It exposes event timing/count/proximity, policy levels/changes, curve level/spreads/inversion/changes, inflation/growth/labor values and surprises, per-series release/vintage metadata, and separate macro stress. If the existing `event_risk` field is empty, it also fills a scheduled/none/unavailable descriptive event record; an already supplied event record is preserved. Market stress, options stress, realized volatility, deterministic regimes, and all non-macro feature values remain untouched. Engine version is 0.18.0; snapshot, statistical feature, options-context, and macro-context schemas are each 1.0.

Synthetic fixtures in `tests/fixtures/macro_scenarios.py` cover calendar clustering, FOMC/CPI, releases, policy changes, yields, and vintages. The manual benchmark is `.venv/bin/python -m benchmarks.macro_context --snapshots 120`. It builds an index for over 1,000 observations, 300 events, 20 vintage/schedule revisions, and at least 100 snapshots, then reports index, event, vintage, curve, surprise, and per-snapshot timings. These local figures are not production latency guarantees. Cross-engine options/seasonality interactions and final ensemble synthesis remain for MCE-19; no attribution or trading logic is introduced here.
