# Market breadth engine (MCE-5)

`BreadthFeatureEngine(config, universe_provider=None, calendar=None).compute(store, as_of_ns)` measures constituent participation using completed, causally available regular-session bars. It reads no wall clock or network provider. The default in-memory provider uses `config.market.universe.breadth`; callers can pass a deterministic `UniverseProvider`. `apply_breadth_to_snapshot(result, snapshot=None)` adds continuous evidence to schema `1.0` snapshots without classifying a breadth or market regime.

## Point-in-time universe membership

`UniverseMembership` carries a canonical symbol, inclusive `effective_from_ns`, exclusive `effective_to_ns`, `available_at_ns`, optional nonnegative finite weight, and source. A member is active at `T` only when `effective_from_ns <= T < effective_to_ns` (or no end) **and** `available_at_ns <= T`. `MembershipTimeline` rejects overlapping intervals for one symbol, including simultaneous duplicates; adjacent records allow a weight change. `members(T)` returns a sorted, immutable `UniverseSnapshot` with source quality. The engine rejects a provider snapshot whose `as_of_ns` differs from the requested `T`. The protocol lets a future historical membership provider supply the same typed snapshot without changing the breadth formulas. No index constituent list is hard-coded or scraped.

Using today's surviving index members for an old date introduces **survivorship bias**: additions, deletions, and historical weights may differ. Historical replay must use membership valid and known at each historical `as_of`, including for the prior breadth observations used in momentum. `available_at_ns` prevents a backfilled membership record learned later from changing an earlier replay result. A source must supply actual point-in-time membership for empirical research; the static config list is appropriate only when its membership assumption is explicitly intended.

The source-level `features.breadth.price_adjustment_status` declares `adjusted`, `raw`, or `unknown` (default). All bars compared for one breadth run must follow one consistent adjustment convention. Historical split/dividend-sensitive breadth requires consistently adjusted constituent and index-proxy prices. MCE-5 does not ingest corporate actions or verify per-bar adjustment metadata; `raw` and `unknown` lower the evidence-quality measure and raise `PROVIDER_DEGRADED` rather than silently claiming adjusted history. A provider must not mix adjustment conventions within the configured source.

## Price and session rules

On an XNYS trading day, each member's current price is the latest completed regular-session bar close available by `as_of_ns`. The comparison price is the bar close ending exactly at the **previous XNYS trading session's regular close**. Both bars must have the configured source, complete interval bounds, positive prices, and effective timestamps at or before `as_of`. This works for one-minute, five-minute, and full-session bars. A daily bar cannot enter an intraday snapshot before its close and effective availability. Premarket and after-hours bars never count. Weekends, holidays, early closes, and DST use the exchange schedule.

At 09:30:10 ET, a bar ending 09:31 is unavailable. A halted or unobserved member is missing; no previous price is carried forward as today's unchanged return. A current bar is stale if either its effective-time age or its interval-end age exceeds `freshness.bar_limit_ns`; the stale member stays in the expected universe but is excluded from all current directional and return statistics. Age exactly at the limit is fresh. A missing prior close also excludes the member. Missing and stale members never become zero returns.

## Formulas and units

Let `V` be valid members with a fresh current price and previous trading-session close, `M` the active point-in-time membership, and `r_i = P_i,current/P_i,previous_close − 1` the unitless simple return. Default unchanged tolerance is `ε = 10⁻⁸`. Counts are `A = #{r_i > ε}`, `D = #{r_i < −ε}`, and `U = #{|r_i| <= ε}`. `advance_fraction = A/|V|`, `decline_fraction = D/|V|`, `net_advance_fraction = (A−D)/|V|`, and `advance_decline_ratio = A/D` only when `D>0`. Fractions are `[0,1]`; net participation is `[-1,1]`; the ratio is nonnegative or `null`. With no valid members, fractions, ratio, and scores are `null`, never fabricated zero.

For each valid member and configured reference horizon `N` (defaults 5, 20, 60 **trading sessions**), the reference is the arithmetic mean of the **N previous completed session closes**, excluding the current session. A member is above when `P_current > SMA_N`; differences within `10⁻¹²` relative are treated as equal to avoid floating summation artifacts. All N prior closes must exist. `above_reference.Nd = above_count/comparable_count` when at least one member has a complete reference; its own comparable count is retained. Equality is not above. A current price is a new `N`-session high when it strictly exceeds the maximum of N prior completed closes, and a new low when strictly below the minimum. Defaults use 20 sessions, so snapshot names explicitly include `.20d`. `new_high_fraction`, `new_low_fraction`, and their difference use only members with complete N-day history.

`participation_score` is exactly `net_advance_fraction`, the raw directional share. The separate headline `breadth_score` combines participation and available reference evidence. Transform each available reference fraction `p` to `2p−1`, multiply by configured weights (default net 0.5, short 0.2, medium 0.2, long 0.1), renormalize over **available** components, and sum. It remains in `[-1,1]`. Each contributor's `contribution` is exactly its transformed value times its effective weight, and contributor terms sum to the score. The score is `null` if valid-member coverage is below the configured 0.8 minimum, membership source quality is `UNUSABLE`, or no component exists. Missing references can leave a score based on the available components, with `INSUFFICIENT_HISTORY` flagged. This score measures participation and reference-level breadth; it does not insert trend or optimize against PnL.

`equal_weight_return = mean(r_i)` and `median_member_return = median(r_i)` over valid members. If **every active member** has an explicit weight and total active weight is positive, `weight_coverage = Σ_valid w_i / Σ_active w_i`. The partial weighted mean is `Σ_valid w_i r_i / Σ_valid w_i`, but it is exposed only when weight coverage meets the configured 0.8 minimum. This renormalization does not hide missing weight: original-universe weight coverage remains visible. Zero weights are allowed and count toward member coverage but contribute no weighted return. A missing weight anywhere makes weighted return and weight coverage unavailable. `equal_weight_divergence = equal_weight_return − weighted_return` only when both exist; it is the point-in-time constituent-weight comparison.

The configurable index proxy defaults to `SPY`. It uses the same current/prior close and freshness rules. `index_proxy_divergence = equal_weight_return − index_proxy_return` and remains distinct from the constituent-weight comparison. `directional_index_divergence = net_advance_fraction − sign(index_proxy_return)` lies in `[-2,2]`; a negative value when the proxy rises and constituents mostly decline exposes narrow leadership. These are context diagnostics, not trading signals.

Contribution concentration uses available `c_i = w_i r_i` when the full point-in-time weight set exists and has positive total, otherwise `c_i = r_i`. Let `a_i = |c_i|/Σ|c_i|`; `contribution_hhi = Σa_i²`, in `[1/|V|,1]`, and `effective_contributors = 1/HHI`, in `[1,|V|]`. If every contribution is zero or no valid member exists, both are `null`. The `contribution_basis` field says `weighted` or `equal`. This narrow absolute-contribution diagnostic is not a full dispersion model.

For each previous trading session endpoint, the engine recomputes a historical advance and net-advance fraction from that endpoint's own point-in-time membership and bars available then. It requires the same minimum member coverage; a missing history point breaks the contiguous history. With short `S=3` and long `L=10` by default, `breadth_momentum = mean(last S net fractions including current) − mean(last L net fractions including current)`. `breadth_acceleration = momentum_current − momentum_previous`, requiring L prior points as well as the current point. `breadth_thrust` uses the same short-minus-long formula on advance fractions. `participation_persistence` is the fraction of the last L net fractions whose sign matches the current nonzero sign; it is zero for a flat current fraction. Momentum and thrust lie in `[-2,2]`; acceleration in `[-4,4]`; persistence in `[0,1]`. They are unavailable without the required contiguous history. No future breadth observations are read. A cumulative A/D line is deferred because it needs explicit replayed state and reset semantics.

## Quality, output, and configuration

`coverage_ratio = |V|/|M|`; the result also exposes expected, available, and stale member counts, and each member's return, weight, reference comparisons, and flags. Low coverage leaves raw partial counts and fractions available but suppresses the headline score. `PARTIAL_UNIVERSE`, `LOW_COVERAGE`, `STALE_DATA`, `MISSING_DATA`, `INSUFFICIENT_HISTORY`, and `PROVIDER_DEGRADED` reuse existing flags. `evidence_quality` is a data-quality diagnostic, not predictive confidence: `member_coverage × reference_coverage × membership_factor × adjustment_factor`. Reference coverage is total comparable reference observations divided by `3 × valid_members` (zero with no valid members). Membership factors are GOOD 1, DEGRADED 0.5, POOR 0.25, UNKNOWN 0.5, UNUSABLE 0; adjustment factor is 1 for declared adjusted data and 0.5 otherwise. Headline data quality is GOOD when the score exists without flags, DEGRADED when it exists with flags, and UNUSABLE when absent.

All `features.breadth` settings are frozen and enter the result-relevant configuration fingerprint: enablement; minimum member/weight coverage; unchanged tolerance; 5/20/60 reference windows; 20-session high/low window; 3/10 momentum windows; index proxy; price-adjustment declaration; and score weights. External point-in-time membership is input data, supplied by the universe provider rather than embedded in the config fingerprint. For reproducible runs, preserve that provider's membership dataset/version alongside the store and config fingerprint.

Snapshot names are stable: `breadth.advance_fraction`, `breadth.decline_fraction`, `breadth.net_advance_fraction`, `breadth.above_reference.5d` (and `.20d`/`.60d`), `breadth.new_high_fraction.20d`, `breadth.equal_weight_return`, `breadth.weighted_return`, `breadth.equal_weight_divergence`, `breadth.index_proxy_divergence`, `breadth.participation`, `breadth.momentum`, `breadth.acceleration`, `breadth.contribution_hhi`, `breadth.effective_contributors`, `breadth.coverage`, and `breadth.weight_coverage`. Unavailable values are omitted from scalar `feature_values`. The typed result retains comparable counts, per-member missingness, quality, and contributor terms. Snapshot projection populates `breadth_score`, `feature_values`, contributors, and quality while preserving prior trend and volatility evidence. Categorical market and breadth regimes stay `UNKNOWN` unless already set by another producer; MCE-5 makes no such classification.
